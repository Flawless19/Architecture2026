При Flash Sale цены меняются каждые 10 минут, поэтому TTL, указанные при обычном режиме, не подходят. 
Я бы отделила кэширование цен и остатков товаров отдельно от кэширование карточек товаров. На карточки и список товаров увеличила бы TTL (например, 2 часа).
И для остатков и цен использовала бы Write-Through подход.

@startuml
title МаркетХаб - кэширование

actor User as user
participant "API Gateway" as api
database "Cache (Redis)" as cache
database "PostgreSQL" as db

user -> api: GET /catalog?category=X
api -> cache: GET catalog:X

alt Cache Hit — данные найдены в кэше
    cache --> api: данные (hit)
    api --> user: ответ (без обращения к БД)
else Cache Miss — данных в кэше нет
    note over cache, db
      Кэш сам обращается к PostgreSQL за данными
      (Read-Through) и сам сохраняет результат у себя.
      API Gateway в поход в БД не участвует.
    end note
    cache -> db: SELECT * FROM products WHERE category = X
    db --> cache: данные из БД
    cache -> cache: SET catalog:X (TTL 10 мин, обычный режим)
    cache --> api: данные (после промаха)
    api --> user: ответ
end

note over api, db
  Реализован паттерн **Read-Through**: при промахе кэш
  самостоятельно обращается к PostgreSQL и кладёт результат
  к себе. API Gateway видит только Cache и не знает,
  откуда пришли данные — hit это был или miss.

  В обычном режиме TTL для списка товаров — 10 минут.
end note

group Flash Sale — цены и остатки
    note over api, cache
      На время Flash Sale TTL для списка товаров и карточек
      увеличивается до 2 часов, так как цены 500 топовых товаров
      меняются каждые 10 минут, а каталог читается постоянно —
      это снижает нагрузку на PostgreSQL.

      Кэширование цен и остатков отделено от кэширования карточек.
      Используется **Write-Through**: при изменении цены/остатка
      данные сначала пишутся в PostgreSQL, затем сразу обновляются в Cache.
    end note

    api -> db: UPDATE products SET price = ... WHERE id = ...
    db --> api: OK
    api -> cache: SET price:product_id (TTL 30 сек)
    cache --> api: подтверждение записи

    note over cache
      В момент Flash Sale TTL для цен/остатков
      значительно сокращается (например, до 30 секунд)
      или кэш для товаров-участников акции отключается.
    end note
end
@enduml
