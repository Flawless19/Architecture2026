## Ситуация

МаркетХаб расширяет функциональность. Команда продукта сформулировала четыре новых требования:

Требование A. Каталог товаров: разные продавцы продают разные типы товаров. Ноутбук имеет атрибуты: процессор, RAM, диагональ экрана. Платье имеет атрибуты: размер, цвет, материал, сезон. Обувь — размер, материал, высота каблука. Текущая схема products с фиксированными колонками не подходит: нужно хранить произвольные атрибуты для каждого типа товара.

Требование B. История действий пользователя: система должна хранить все события пользователей — просмотр товара, добавление в корзину, оформление заказа, поиск. Ожидаемый объём: 50 миллионов событий в месяц. Нужна фильтрация по user_id и временному диапазону.

Требование C. Рейтинг продавцов в реальном времени: «Топ-50 продавцов по числу завершённых заказов за сегодня» — обновляется каждую минуту, отображается на главной странице.

Требование D. Сессии пользователей и токены авторизации: хранить JWT-токены сессий. Нужен быстрый lookup по токену (< 5 мс), автоматическое истечение через 24 часа.

Ваша задача: для каждого требования предложить подходящее хранилище — PostgreSQL, MongoDB, Cassandra или Redis — и обосновать выбор.

Подсказка: для одного из требований правильный ответ — «оставить в PostgreSQL, NoSQL избыточен».
